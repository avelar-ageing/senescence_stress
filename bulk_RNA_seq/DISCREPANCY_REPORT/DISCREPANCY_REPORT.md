## 2. Ensembl gene dictionary — gap found, then closed exactly

The original pipeline pinned biomaRt to `apr2020.archive.ensembl.org` (Ensembl release
~100) for the protein-coding gene dictionary. That interactive archive+biomart service is
now decommissioned. **Fix:** Ensembl's plain FTP file archive for the same release is still
live (`ftp.ensembl.org/pub/release-100/`); `get_ensembl_release_pc()`
(`bulk_RNA_seq/R/functions.R`) parses the release-100 GTF directly instead.

**Verified exact:** 13,681/13,681 (100.0%) of the gene symbols in `cq_samples.rds` (the one
object surviving from the original run) are reproduced by this GTF-derived dictionary.
This mattered in practice — an earlier rerun using a live (different-version) Ensembl
release gave DEG counts close to but not identical to the paper (~1-2% off on every
number); after the exact pin, every DEG count below matches exactly.

**Remaining, smaller approximation:** Entrez ID cross-referencing (for KEGG/GO enrichment
only, not the DEG-calling object) uses `org.Hs.eg.db`'s current symbol→Entrez mapping,
since Ensembl's GTF doesn't carry Entrez IDs. This did not visibly affect the enrichment
results below (top terms and directionality match the paper).

## 7. recount3 count scaling — verified correct (see also earlier audit)

Confirmed via [recount3 docs](http://research.libd.org/recount3/reference/transform_counts.html):
`transform_counts()` requires the `raw_counts` assay (base-pair coverage, not read counts)
and by default rounds AUC-scaled output to integers. The meta-analysis pipeline applies it
at the right stage (`process_rse()`, after gene/sample subsetting — which only subsets rows/
columns, never touches values — and before any DESeq2 modeling) on the correct 34-study
pooled multi-study object. The single-study temporal pipeline correctly skips it
(`scale_counts=FALSE`), relying on DESeq2's own size factors instead.

## 8. tAge — new analyses, not paper reproductions, but internally consistent

- **Retracted an unverified claim mid-way through this work**: initially applied
  `scale_counts=TRUE` to the temporal tAge computation on the unchecked assumption the EN
  clock was trained on recount3-AUC-scaled data. Checked the tAge package docs/README
  directly — no such requirement exists anywhere in them. Corrected to `scale_counts=FALSE`
  (consistent with the DEG-calling pipeline's own convention for this single-study
  dataset). Empirically, the two settings gave nearly identical results (biggest shift: one
  borderline p.adj moved 0.099→0.14, nothing else changed materially) — consistent with the
  corrected reasoning that tAge's own internal RLE normalization already does the
  depth-normalization job regardless of upstream scaling convention.
- **Meta-analysis, all 6 conditions**: every arrest/senescence condition shows
  significantly elevated tAge vs. Proliferating (BH-adj p<0.01, 9/10 tests). Pairwise
  (all 15 condition pairs): senescence subtypes (RS/SIPS/OIS) and CICQ don't
  significantly differ from each other; SSCQ is the outlier (lowest tAge among arrest
  states, most often distinguishable from the others).
- **Temporal, by cell type × timepoint**: Fibroblasts show a clean monotonic tAge increase
  over time (all 3 timepoints BH-adj p<0.011); Keratinocyte/Melanocyte are noisier/
  non-monotonic on the `scaled_diff` model specifically.
